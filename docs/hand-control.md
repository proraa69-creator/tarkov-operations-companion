# Raid OS — Hand Control (тестовая сборка)

Статус: экспериментальная функция, только в отдельной тестовой сборке **Raid OS Hand Control Test**.
Основная сборка (`npm run build`, `npm run dist:win`) её не содержит: ни кода, ни модели.

## Главный инвариант

Hand Control управляет **только интерфейсом Raid OS** на втором мониторе и **не отбирает у игры
фокус, мышь и клавиатуру**:

- системный курсор не двигается, OS-события мыши/клавиатуры не создаются (`SendInput`, `sendInputEvent` не используются);
- окно Raid OS не активируется: события доставляются только в DOM самого приложения;
- нажатие рукой не может открыть браузер, системный диалог, новое окно или нативный `confirm/alert`
  (защита в `electron/handControlGuard.ts` и в `uiDispatcher.click`);
- поля ввода, выпадающие списки, внешние ссылки, встроенный web view и карта Leaflet недоступны для руки;
- видео с камеры обрабатывается в памяти и никуда не отправляется и не сохраняется.

## Жесты (по записи пользователя)

| Действие | Жест |
|---|---|
| Наведение | курсор ведёт **центр ладони**: пальцы курсор не двигают, кисть на экране стоит на месте |
| Нажатие (тап) | быстро согнуть указательный палец и разогнуть (остальные пальцы уже согнуты). Нажатие — на сгибе, клик — на разгибе |
| Прокрутка шагом | поднять указательный и средний пальцы и быстро согнуть-разогнуть оба |
| Плавная прокрутка | с поднятыми двумя пальцами двигать руку вверх/вниз |
| Зум карты | быстро отвести большой палец от указательного — приблизить; быстро свести — отдалить (медленно — не считается) |
| Перетаскивание карты | раскрытая ладонь + быстрый толчок к камере = «зажата кнопка мыши»; ведите рукой; отвести руку назад или сжать кулак — отпустить |
| Отмена | кулак (пальцы сжимаются вместе) — сбрасывает нажатие, захват и прокрутку; пока кулак сжат, ничего не начинается |
| Тычок (опция) | толчок всей рукой к экрану; включается в настройках «Нажатие: Тычок/Оба» |

Защита от залипания и случайных команд (по результатам теста на реальном ПК):
- **никакой фиксации, пока рука движется**: прицел «придерживается» только если ладонь стояла на месте
  перед жестом, и сразу отпускается, если рука поехала; максимум 0,3 с;
- толчок (тычок, захват ладонью) засчитывается только быстрым (≤ 0,3 с) и на месте — обычный дрейф
  руки к монитору при ведении не считается;
- режим прокрутки сам завершается, если двух пальцев нет 0,7 с;
- палец, согнутый дольше 1 с, отменяет нажатие; слабый трекинг или потеря руки — ничего не начинается.
- **наклон кисти — не жест**: если вся ладонь повернулась (например, кисть согнута в запястье вниз из
  вертикального положения и указательный палец ушёл к камере), тап, фиксация, взмах, щипок и толчок не
  засчитываются. Жест пальцами засчитывается, только если ладонь повернулась не более чем на 35° и палец
  согнулся минимум вдвое сильнее, чем повернулась ладонь (на реальных тапах ладонь поворачивается на 16–29°).

Пороги тапа и взмаха подобраны по записи реальных жестов; запись (только координаты) хранится как
регрессионный тест `src/handControl/recordedGestures.test.ts`: ровно 4 нажатия, 4 шага прокрутки,
ни одного ложного события за 11 с наведения.

## Архитектура

```
веб-камера ─► WebcamHandTracker ─► handWorker (MediaPipe в отдельном потоке, GPU→CPU)
            ─► HandGestureEngine (1€-фильтр, калибровка, тап/взмах/прокрутка)
            ─► HandFrame (контракт) ─► HandUiDispatcher (DOM: hit test, hover, click, scroll)
                                    └► HandControlLayer (призрачная рука / курсор, статус, Стоп)
```

`HandFrame` (`src/handControl/types.ts`) — единый контракт. Позже iPhone может стать вторым
источником тех же кадров без изменений UI-слоя.

| Файл | Назначение |
|---|---|
| `src/handControl/webcamTracker.ts` | камера, передача кадров в поток распознавания, запасной режим в основном потоке |
| `src/handControl/handWorker.ts` | MediaPipe в Web Worker: загрузка модели и распознавание не тормозят интерфейс |
| `src/handControl/calibration.ts` | калибровка по двум углам: угол засчитывается после остановки ладони |
| `src/handControl/gestureEngine.ts` | распознавание жестов, состояния point/press/scroll |
| `src/handControl/handGeometry.ts` | сгиб пальцев, оценка глубины, калибровка |
| `src/handControl/uiDispatcher.ts` | доставка событий в DOM Raid OS, блок-лист элементов |
| `src/handControl/handControlStore.ts` | запуск/стоп, настройки (`localStorage`), калибровка |
| `src/handControl/HandControlLayer.tsx` | призрачная рука, курсор, статус и кнопка «Стоп» |
| `src/handControl/HandControlPanel.tsx` | панель на странице «Эксперименты», диагностика и тестовая зона |
| `electron/handControlGuard.ts` | запрет диалогов/браузера/новых окон сразу после нажатия рукой |

Изменения в существующем коде минимальны: ленивое подключение слоя в `App.tsx` и панели в
`ExperimentalPage.tsx` (только при флаге сборки), разрешение камеры только для главного окна и
только видео, защита фокуса в `electron/main.ts`, `handControl` в preload.

## Сборка и запуск

```
npm run dev:hand        # браузер/разработка, режим handtest
npm run desktop:hand    # собрать и запустить Electron локально
npm run dist:win:hand   # Windows portable: release-hand/Raid OS Hand Control Test <версия>.exe
```

Тестовая сборка имеет свой `appId` и имя, поэтому хранит настройки отдельно и ставится рядом с
основной. Без автообновления. GitHub Actions (`.github/workflows/hand-control-test.yml`) собирает
exe при пуше в `feature/hand-control-test` и выкладывает его как artifact.

`npm run hand:assets` копирует WASM MediaPipe из `node_modules` и один раз скачивает модель руки
(проверка SHA-256) в `public-hand/` (не коммитится).

## Как тестировать

1. Запустить игру на мониторе 1 (лучше «Оконный без рамки»), Raid OS Hand Control Test — на мониторе 2.
2. «Эксперименты» → Hand Control → «Включить камеру». Камеру лучше поставить на второй монитор.
3. «Калибровка»: поставить руку в удобную точку для левого верхнего угла и задержать ладонь, затем то же для правого нижнего. Указатель во время калибровки двигается.
4. Проверить наведение, тап и прокрутку в «Тестовой зоне», затем на страницах «Задания» и «Обзор».
5. Переключиться в игру мышью и проверить, что строка «Активное окно Windows» показывает игру, а не Raid OS.

## Что нужно измерить на реальном ПК

- FPS игры с Hand Control и без (режимы «Видеокарта» и «Процессор»);
- время распознавания (мс) и кадры/с в диагностике;
- ложные нажатия за 10 минут игры с рукой в кадре и без;
- поведение при занятой камере (OBS), при слабом свете, при двух мониторах с разным DPI;
- игра в полноэкранном режиме: фокус и отрисовка Raid OS на втором мониторе.

## Известные ограничения

- Нужна видимая (не свёрнутая) Raid OS на втором мониторе.
- Камеру может держать другая программа (OBS) — тогда нужна вторая камера или виртуальная камера OBS.
- Распознавание идёт на игровом ПК и потребляет ресурсы; без руки в кадре анализируется каждый третий кадр.
- Поля ввода и действия с подтверждением (`confirm`) рукой недоступны. На карте доступны маркеры, зум и перетаскивание.
