# Выпуски Claude без доступа к SSH

Статус: настройка и первый end-to-end выпуск в работе. Не считать готовым, пока в WORK_LOG нет результата smoke release.

Ветка публикации: `release/production`. Ветка `sync/codex-claude-context` остаётся обменом контекстом; `main` пока не отражает весь актуальный production overlay.

1. Прочитать LATEST, PROJECT_STATE, COORDINATION и WORK_LOG. Сравнить собственную ветку с `release/production`, не перетирать чужие коммиты.
2. Перенести только готовые изменения обычным merge/cherry-pick. Выполнить локальные проверки. Push в `release/production` разрешён владельцем для автоматического выпуска после тестов.
3. Дождаться `RaidOS Production Gate` в Actions. Красный или незавершённый запуск не разрешает выпуск.
4. VPS проверяет exact SHA успешного push в этом репозитории, хэш доверенного workflow и ancestry последнего рабочего выпуска. Проверка ветки выполняется на VPS раз в 2 минуты; это не старый 15-минутный агент ноутбука.
5. Зависимости, сайт и обе Windows-редакции собираются отдельным пользователем `raidos-build`, без доступа к ключам и базе. Root-owned publisher проверяет пакет, подписывает клиент, делает согласованный SQLite backup и выпускает API, сайт и EXE.
6. При ошибке публикации восстанавливаются исходники, зависимости API, сайт и обе загрузки. Текущая база не заменяется резервной копией, чтобы не потерять новые аккаунты и платежи. Миграции должны быть обратно совместимыми; деструктивные миграции требуют отдельного ручного выпуска.

Ключей VPS и GitHub secrets этому механизму не нужно. Работает при выключенном ноутбуке. Изменения самого workflow, signing key, установленных release scripts и неизвестных путей требуют review оператора; они не применяются автоматически. Один неудачный SHA не запускается бесконечно: исправить причину и выпустить новый коммит.

Контроль: Actions run, `https://raidos.app/download/version.json`, `https://raidos.app/api/health`. На VPS: `systemctl status raidos-release.timer`, `/var/lib/raidos-release/state.json` (только оператор), `journalctl -u raidos-release.service`. Не экспортировать private build logs или данные пользователей в общий контекст.

Windows клиент: https://raidos.app/download/windows. Владелец получает серверную редакцию через защищённую кнопку админ-панели, не через публичную постоянную ссылку.

Мобильная сборка и реальные native проверки в EFT не входят в автоматическую публикацию Windows/site/API.
