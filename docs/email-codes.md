# Коды подтверждения на e-mail (Resend)

Что умеет сервер, когда подключён почтовый сервис:

- **Подтверждение e-mail при регистрации.** На сайте после формы регистрации появляется шаг «Проверьте почту»:
  код из 6 цифр из письма → аккаунт создаётся и сразу выполняется вход. Пока код не введён, аккаунта нет
  (незавершённая регистрация хранится 30 минут). Есть кнопка «Отправить код ещё раз» (не чаще раза в минуту).
  Приложения регистрируют через сайт, поэтому шаг с кодом — тоже там.
- **«Подтвердите e-mail»** — для аккаунтов, созданных раньше (или пока почта была выключена): плашка в личном
  кабинете на сайте и в приложении. Пока ничего не блокируется, кроме прав владельца (см. ниже).
- **Вход по коду из письма** (без пароля): сайт → «Вход» → «Войти по коду из письма»; в приложении — ссылка под
  формой входа.
- **«Забыли пароль?» по e-mail:** e-mail → код → новый пароль. Все прежние входы на всех устройствах завершаются.
  Аккаунт владельца **может** восстановить пароль по e-mail (почта — его основной способ входа), но не по SMS.

Пока почтовый сервис не подключён, всё работает как раньше: регистрация сразу создаёт аккаунт (e-mail не
подтверждён), кнопки входа и восстановления по коду из письма скрыты (`emailEnabled: false` в
`GET /v1/accounts/auth-config`).

## Что нужно сделать владельцу

### 1. Зарегистрироваться в Resend

1. Откройте <https://resend.com> → **Sign up** → **Continue with Google** → аккаунт **raidosapp@gmail.com**.
2. Бесплатного тарифа для начала хватает (на момент написания — 3 000 писем в месяц и 100 в сутки; актуальные
   условия смотрите на странице Pricing). Если тариф бесплатный, поставьте в панели лимит **не больше 100 писем в
   сутки**.

### 2. Добавить домен raidos.app

1. В Resend: **Domains → Add Domain** → `raidos.app`, регион **Ireland (eu-west-1)**.
2. Resend покажет записи DNS (точные значения копируйте из Resend — они свои для каждого домена). Обычно это:

   | Тип | Имя (Name) | Значение | Примечание |
   | --- | --- | --- | --- |
   | TXT | `resend._domainkey` | `p=MIGfMA0GCSqGSIb3…` (длинный ключ DKIM) | подпись писем |
   | MX | `send` | `feedback-smtp.eu-west-1.amazonses.com`, приоритет 10 | возвраты (bounce) |
   | TXT | `send` | `v=spf1 include:amazonses.com ~all` | SPF |
   | TXT | `_dmarc` | `v=DMARC1; p=none;` | необязательно, но желательно |

3. В **Cloudflare** → сайт `raidos.app` → **DNS → Records → Add record** добавьте каждую запись как есть.
   **Proxy status — «DNS only»** (серое облако): почтовые записи нельзя пропускать через прокси Cloudflare.
   В поле Name указывайте только поддомен (`send`, `resend._domainkey`, `_dmarc`) — Cloudflare сам допишет
   `.raidos.app`. Не трогайте существующие записи сайта и туннеля.
4. В Resend нажмите **Verify DNS Records**. Обычно проверка проходит за несколько минут, иногда до нескольких часов.
   Пока домен не подтверждён (статус не **Verified**), письма от `noreply@raidos.app` не отправляются.
5. В настройках домена в Resend оставьте **Click Tracking** и **Open Tracking** выключенными (по умолчанию они
   выключены): в письмах Raid OS нет пикселей слежения и отслеживаемых ссылок, и так должно оставаться.

### 3. Создать API-ключ

1. Resend → **API Keys → Create API Key**.
2. Имя — например `raidos-server`, **Permission: Sending access**, **Domain: raidos.app** (только отправка и только с
   этого домена — полный доступ серверу не нужен).
3. Скопируйте ключ (начинается с `re_…`). Resend показывает его **один раз**.

> Ключ — это доступ к отправке писем от имени raidos.app. Не отправляйте его в чат и никому не показывайте. Если ключ
> утёк — удалите его в Resend (API Keys → … → Delete), создайте новый и введите заново в панели.

### 4. Вставить ключ на ноутбуке-сервере (только там!)

Приложение Raid OS Server → кнопка **«Сервер»** → «Сервер и сайт на этом компьютере» → панель
**«Почта: коды подтверждения»** (рядом с «SMS: одноразовые коды») → **«Настроить»**:

- **Почтовый сервис:** Resend;
- **API-ключ:** `re_…`;
- **Отправитель (From):** по умолчанию `Raid OS <noreply@raidos.app>` — домен должен совпадать с подтверждённым;
- **Лимит писем в сутки:** по умолчанию 500 (на бесплатном тарифе Resend — не больше 100).

«Сохранить» — ключ шифруется средствами Windows (DPAPI, как ключи SMS), сервер перезапускается
и подхватывает настройки. Строка состояния показывает «Включено: Resend · … · отправлено за сутки N / лимит».

### 5. Проверить

1. В той же панели введите свой адрес и нажмите **«Отправить тестовое письмо»**. Если письмо пришло — всё работает
   (проверьте и папку «Спам»). Тестовое письмо учитывается в суточном лимите. Если Resend ответит ошибкой, в панели
   появится её HTTP-код и название (например `403, validation_error` — домен ещё не подтверждён или ключ не для этого
   домена; `401` — неверный ключ; `429` — превышен лимит Resend).
2. На сайте в приватном окне: зарегистрируйте тестовый адрес → придёт код → аккаунт создан.
3. В своём кабинете нажмите «Отправить код» в плашке «Подтвердите e-mail» и подтвердите адрес владельца.

## Права владельца и подтверждение e-mail

Права владельца (e-mail из «E-mail владельца», `TARKOV_OWNER_EMAILS`) теперь получает только аккаунт, который
**подтвердил e-mail кодом**, или аккаунт, **созданный до появления кодов на e-mail**. Второе нужно, чтобы ваш
существующий аккаунт владельца продолжил работать: при первом запуске нового сервера все уже существующие аккаунты
помечаются как «старые» (`email_grandfathered`), и это происходит ровно один раз. Новые аккаунты такой отметки не
получают никогда.

Пока почта выключена, адрес из списка владельцев нельзя зарегистрировать заново (как и раньше). Когда почта
включена, такой адрес можно зарегистрировать — код подтверждения придёт только настоящему владельцу ящика.

Подтвердить свой адрес всё равно стоит: после этого «Забыли пароль?» по e-mail гарантированно вернёт доступ.

## Защита

- Код — 6 цифр (криптографически случайный), действует **10 минут**, после **5 неверных попыток** перестаёт
  действовать. В базе хранится только хэш кода с солью; код привязан к адресу и к цели (регистрация / подтверждение /
  вход / сброс).
- Повторный код — не чаще раза в **60 секунд**, не больше **10 кодов в сутки** на адрес, ограничения по IP-адресу
  посетителя (15 минут и сутки), **суточный бюджет писем** на весь сервис (лимит в панели). Когда бюджет исчерпан,
  коды не отправляются до следующих суток, вход по паролю работает как обычно.
- **Не раскрывается, зарегистрирован ли адрес.** Регистрация отвечает одинаково для нового, занятого и
  владельческого адреса: «Мы отправили код на e-mail». На занятый адрес код не отправляется и аккаунт не создаётся —
  вместо этого владелец ящика получает письмо «Кто-то пытался зарегистрироваться с вашим адресом» (не чаще раза в
  сутки). Вход и сброс по коду тоже отвечают одинаково для любого адреса; письмо уходит только существующему
  незаблокированному аккаунту. Время ответа от этого не зависит.
- Заблокированные аккаунты не получают писем и не могут войти по коду.
- Адреса, коды и ключи не пишутся в журналы сервера; при ошибке Resend в журнал попадает только «resend» и HTTP-код.
- Письма — простой HTML и текст, на русском с одной строкой на английском, без картинок, внешних ресурсов и пикселей
  слежения.
- Настройки почты есть **только** в приложении на ноутбуке и передаются серверу через переменные окружения. В
  админ-панели сайта их нет: даже украденная сессия владельца на сайте не позволит перехватить коды.

## Переменные окружения (для запуска сервера вручную)

Приложение владельца задаёт их само. Для `npm run server:dev` можно указать вручную:

| Переменная | Значение |
| --- | --- |
| `TARKOV_EMAIL_PROVIDER` | `resend`; не задана — коды на e-mail выключены, регистрация без подтверждения |
| `TARKOV_EMAIL_API_KEY` | API-ключ Resend (`re_…`, доступ Sending access) |
| `TARKOV_EMAIL_FROM` | отправитель, по умолчанию `Raid OS <noreply@raidos.app>` |
| `TARKOV_EMAIL_DAILY_LIMIT` | писем в сутки на весь сервис, по умолчанию 500 |
| `TARKOV_EMAIL_ADDRESS_DAILY_LIMIT` | кодов в сутки на один адрес, по умолчанию 10 |

Другой почтовый сервис (например, Unisender Go) добавляется одним файлом в `server/src/services/email/` — интерфейс
`EmailSender` (см. `types.ts`).

## Состояние проверки

Запрос к Resend написан по публичной документации: `POST https://api.resend.com/emails`, заголовок
`Authorization: Bearer re_…`, тело JSON `{ from, to: [адрес], subject, html, text }`, ответ `{ id }`.
**Вживую он не проверялся** — среда разработки не имеет доступа к resend.com. Всё покрыто тестами с поддельным
отправителем (`server/src/routes/email.test.ts`). Первая настоящая проверка — кнопка «Отправить тестовое письмо».
