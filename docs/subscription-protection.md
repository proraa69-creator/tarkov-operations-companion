# Защита платных данных и подписки

Как Raid OS ограничивает приложение без подписки и что от этого реально можно ожидать.

## Главное честно

- **Невзламываемой проверки на стороне клиента не бывает.** Любой exe можно разобрать, пропатчить и запустить
  в отладчике. Всё, что делает приложение у игрока, — это неудобства для взломщика, а не стена.
- **Данные tarkov.dev публичны.** Задания, предметы, карты и цены лежат в открытом API tarkov.dev и в вики. Мы не можем
  «спрятать» сами факты о квестах — кто угодно может взять их оттуда напрямую.
- **Настоящая защита — наш сервер.** Платная версия приложения получает данные и сервисы только с нашего сервера и только
  для аккаунта с действующей подпиской. Без подписки сервер ничего не отдаёт, а в exe нет базы, которую можно достать.
  Ценность подписки — в удобстве и в нашей обработке (каталог с вики, карты, план рейда, прогресс по логам,
  синхронизация, мобильная версия), а не в «секретности» данных tarkov.dev.

## Что сделано

### 1. Шлюз данных на сервере

- `POST /v1/data/graphql` — запросы к GraphQL tarkov.dev, `GET /v1/data/json/<regular|pve|pvp-season>/<набор>` — файлы
  json.tarkov.dev (каталог, переводы, отчёты о Гунах). Каталог — `GET /v1/catalog/<режим>` (`?lang=en` — английский),
  поиск игроков — `/v1/players/*`.
- Все эти адреса требуют: вход в аккаунт (иначе 401), доступ — владелец, стример, оплаченный период или пробный период
  (иначе **402 «Нужна подписка»**), активное устройство аккаунта в заголовке `X-Raid-Device` (иначе 403; аккаунту
  владельца устройство не нужно).
- Лимиты: на IP (считаются первыми, до проверки сессии) и на аккаунт; ответ больше лимита размера отклоняется.
- Общий кэш на сервере для всех игроков: цены — 10 минут, статичные данные — 6 часов; одинаковые запросы в полёте
  объединяются в один запрос к tarkov.dev.
- Разрешены только запросы на чтение: одна операция, без `mutation` / `subscription` / интроспекции (`__schema`,
  `__type`). Запрос проходит, если его имя есть в списке `ALLOWED_OPERATIONS`
  (`server/src/services/dataGateway.ts`) **или** все поля верхнего уровня из безопасного набора (`items`, `tasks`,
  `traders`, `maps`, `barters`, `crafts`, `hideoutStations`, `ammo`, `historicalItemPrices`, `bosses`, `playerLevels`,
  `itemPrices`, `item`, `task`, `fleaMarket`). Новый запрос в приложении — назовите его `query RaidOsЧтоТо …` и добавьте
  имя в `ALLOWED_OPERATIONS` (или используйте только безопасные поля).
- Сайту эти адреса не нужны: сайт работает как раньше.

### 2. Слой данных в приложении

- Единственная точка чтения tarkov.dev — `src/data/tarkovApi.ts` (`tarkovGraphql()`, `tarkovJson()`).
- **Версия для игроков** (собранный exe-клиент, телефон, любая сборка не владельца) ходит только через шлюз сервера с
  сессией аккаунта. **Версия владельца и режим разработки** — как раньше, напрямую (и сначала через сервер, где он есть).
- Защита от «забытых» прямых запросов: `installTarkovFetchGuard()` перехватывает любые `fetch` на `api.tarkov.dev/graphql`
  и `json.tarkov.dev` и отправляет их через шлюз — новые разделы (экономика, баллистика, сборка оружия) автоматически идут
  через сервер, даже если вызывают `fetch` сами. `players.tarkov.dev` из приложения запрещён. В собранном exe основной
  процесс Electron дополнительно отменяет любые запросы страницы к этим хостам; картинки `assets.tarkov.dev` разрешены.
- Поиск профиля по нику в exe игрока — только через сервер (прямой запасной путь к tarkov.dev остался в версии
  владельца).

### 3. Локальный кэш

- В exe игрока каталог, переводы и прочие игровые данные хранятся в `%APPDATA%\Tarkov Operator\game-cache`
  **зашифрованными через Electron safeStorage (DPAPI Windows)**. Срок жизни записи — не позже окончания подписанного
  допуска. Без действующего допуска кэш ничего не отдаёт; выход из аккаунта, 402, отключение устройства и «Очистить
  данные» стирают его.
- Старые незашифрованные кэши прошлых версий (IndexedDB) удаляются при запуске.
- На телефоне — память + IndexedDB внутри приложения, тоже со сроком не позже допуска.
- Если ОС не даёт шифрование (редкий Linux), кэш живёт только в памяти до закрытия приложения.

### 4. Подписанный допуск (entitlement) и устройства

- Сервер выдаёт токен, подписанный Ed25519: `{аккаунт, устройство, план, выдан, истекает}`. Срок — максимум 72 часа
  (работа без интернета), но никогда не дольше конца оплаченного периода + 1 день (пробный период — до его конца).
  Приложение обновляет его раз в 3 часа и сразу после входа.
- Приложение проверяет подпись, устройство, срок и то, что часы не переведены назад.
- **Ключ подписи** сервер создаёт при первом запуске: файл `entitlement-ed25519.pem` (права 0600) рядом с базой. На
  ноутбуке-сервере приложение владельца хранит ключ зашифрованным (safeStorage, `entitlement-key.bin` в данных
  приложения) и передаёт серверу через `TARKOV_ENTITLEMENT_PRIVATE_KEY`; ключ, который сервер создал раньше, при этом
  переносится, а открытый файл удаляется. **В репозиторий ключ не попадает никогда.**
- **Открытый ключ**: `GET /v1/entitlement/public-key`. Приложение запоминает его при первом входе на сервер (TOFU) и
  дальше отказывается принимать другой («Ключ сервера изменился»). Выход из аккаунта забывает запомненный ключ этого
  сервера. Чтобы не доверять «при первом входе», ключ можно встроить в exe при сборке:
  `RAIDOS_ENTITLEMENT_PUBLIC_KEY=<43 символа из /v1/entitlement/public-key>` или
  `RAIDOS_ENTITLEMENT_PUBLIC_KEY_FILE=<файл с ключом или с JSON ответа>` (вместе с `TARKOV_DEFAULT_SERVER_URL`,
  по умолчанию https://raidos.app). Для телефона — `VITE_ENTITLEMENT_PUBLIC_KEY`.
- **Лимит устройств: 3 активных на аккаунт.** У каждой установки свой случайный идентификатор (хранится через
  safeStorage). Вход на четвёртом устройстве отключает то, которым пользовались давнее всех: его сессия завершается,
  приложение на нём показывает «Это устройство отключено…», а на новом устройстве появляется уведомление, какое
  устройство отключено. Новых/повторно включённых устройств — не больше 10 в сутки на аккаунт. У аккаунта владельца
  лимита нет. Число можно поменять переменной `TARKOV_MAX_DEVICES` на сервере.

### 5. Укрепление exe игрока

- Electron fuses в сборке (`package.json` → `build.electronFuses`): `RunAsNode` выключен, `NODE_OPTIONS` и `--inspect`
  игнорируются, включены проверка целостности `app.asar` (встроенный хэш) и загрузка приложения только из `app.asar`,
  шифрование cookies.
- В собранном exe игрока нет DevTools, клавиши F12 / Ctrl+Shift+I / Ctrl+R / F5 не работают, меню приложения нет.
- В собранном интерфейсе нет source maps, вызовы `console.*` и `debugger` вырезаны.

### 6. Экран оплаты

- Exe игрока без подписки открывается на входе в аккаунт, затем — экран подписки: тарифы на 1 / 3 / 6 / 12 месяцев
  (цены с сервера), кнопка «Оплатить» открывает оплату в личном кабинете на сайте, подсказка про 3 бесплатных дня по
  ссылке стримера. Все игровые разделы закрыты с понятным объяснением. После оплаты приложение открывается само в
  течение минуты (или по кнопке «Проверить оплату»).
- Версия владельца и аккаунты стримеров не затронуты (стримеры — бесплатно навсегда, план `streamer`).

## Важно: существующие пользователи

После обновления **все аккаунты без оплаченного периода, пробного периода или статуса стримера увидят экран оплаты**.
Это ожидаемо. Чтобы открыть доступ:

- **Выдать дни**: сайт → «Админ-панель» → «Пользователи» → пользователь → «Выдать / продлить подписку» (число дней и
  причина; попадает в журнал). Допуск обновится в приложении в течение минуты.
- **Стример**: приглашение стримера из панели владельца — доступ бесплатно навсегда.
- **Пробный период**: пользователь указывает код приглашения стримера в кабинете — 3 дня.

## Как посмотреть и отключить устройства

Сайт → «Админ-панель» → «Пользователи» → пользователь → блок «Устройства»: название (ОС, имя компьютера, версия),
последнее использование, активно или отключено и почему. «Отключить» завершает сессию этого устройства; действие
пишется в журнал («Отключено устройство»). Сам пользователь видит свои устройства через `GET /v1/accounts/me/devices`.

## Что НЕ защищено (честно)

- **Публичные данные**: всё, что есть в tarkov.dev и вики, можно взять оттуда напрямую без нас.
- **Платящий пользователь может сохранить то, что видит**: скриншоты, копирование текста, перехват ответов своего же
  приложения, пока подписка активна. Сервер отдаёт данные тому, кто заплатил.
- **Взлом клиента**: можно пропатчить exe (убрать экран оплаты), подменить ответы, запустить свой «сервер» с тем же
  API или перехватить DPAPI-шифрование под своим пользователем Windows. Но без подписки на нашем сервере такой клиент
  получит только то, что он сам где-то взял, — нашей обработки и синхронизации у него не будет.
- **Шифрование кэша** защищает от копирования файлов на другой компьютер/пользователя и от «просто открыть JSON»,
  но не от программы, запущенной под тем же пользователем Windows.
- **Общий аккаунт**: лимит в 3 устройства и отключение самого старого делают передачу пароля неудобной, но не
  невозможной (можно входить по очереди, не чаще 10 новых устройств в сутки).
- **TOFU-ключ** защищает от подмены ключа на уже известном сервере, но не от входа на другой (поддельный) адрес
  сервера; встроенный в exe ключ закрывает это для сервера по умолчанию.
- **Офлайн-режим**: 72 часа приложение работает без интернета с последним допуском и кэшем — это сделано намеренно.

## Что требует проверки на реальной сборке

- Fuses и проверка целостности `app.asar` применяются только при упаковке electron-builder для Windows; в этой среде
  они не проверялись на настоящем exe. После сборки убедитесь, что exe запускается, и (по желанию) проверьте fuses:
  `npx @electron/fuses read --app "release/win-unpacked/Raid OS.exe"`.
- Файлы из `asarUnpack` (tesseract, koffi, uiohook, локальный сервер) проверкой целостности `app.asar` не покрываются.
- `safeStorage` на Windows всегда доступен (DPAPI); на Linux без keyring токен и кэш живут только в памяти.
