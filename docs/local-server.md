# Локальный сервер: API и сайт на своём компьютере

Хостинга нет: API-сервер и сайт с личным кабинетом работают на компьютере владельца (Windows).
Приложение — «оболочка»: оно считывает то, что может только оно (журналы EFT, скриншоты с позицией,
распознавание экрана, горячие клавиши и оверлеи), отправляет это на сервер и читает данные обратно.
Личный кабинет на сайте показывает те же данные. PvP, PvE и Сезон хранятся раздельно.

## Что нужно

- Windows 10/11, Windows PowerShell 5.1 (есть в системе) или PowerShell 7.
- Node.js **22.13 или новее** (LTS). Встроенный модуль `node:sqlite` нужен для базы данных.
- Один раз установить зависимости из корня репозитория:

```powershell
npm install
npm --prefix server install
```

## Запуск и остановка

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
```

Скрипт запускает два фоновых процесса и выводит адреса:

| Что | Адрес | Команда внутри |
| --- | --- | --- |
| API-сервер | http://127.0.0.1:8787 | `npm --prefix server start` |
| Сайт и личный кабинет | http://localhost:5202 | `npm --prefix website run dev` |

- Если порт уже занят, скрипт считает сервис запущенным и не стартует его второй раз.
- `WEB_ORIGIN` (CORS) разрешает только локальный сайт (`localhost:5202`) и dev-сервер интерфейса приложения
  (`localhost:5173`). Само приложение обращается к серверу из main-процесса Electron, CORS ему не нужен.
- Сервер слушает только `127.0.0.1` — из сети и из интернета он недоступен.
- Журналы процессов: `server\data\logs\`.

Остановить оба процесса:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-local.ps1 -Stop
```

## Как подключается приложение

1. Зарегистрируйтесь на сайте: http://localhost:5202/register (в приложении: Профиль → «Аккаунт сервера» →
   «Регистрация на сайте»).
2. В приложении: Профиль → «Аккаунт сервера» → e-mail и пароль → «Войти».
   Там же видно состояние: «Сервер доступен» или «Сервер недоступен».
3. Адрес сервера по умолчанию — `http://127.0.0.1:8787`. Другой адрес задаётся переменной окружения
   `TARKOV_API_URL` (разрешены только HTTPS или `http://localhost` / `http://127.0.0.1`).
   Адрес сайта для кнопок — `TARKOV_WEBSITE_URL` (по умолчанию `http://localhost:5202`).

Сессия (токен) хранится только в main-процессе приложения и на диске — зашифрованной через Electron
`safeStorage` (DPAPI Windows) в папке данных приложения (`server-session.bin`). В интерфейс и в
`localStorage` токен не попадает, пароль нигде не сохраняется. Если в системе нет защищённого хранилища,
вход действует только до закрытия приложения.

Что отправляет приложение после входа (всё раздельно для PvP / PvE / Сезона):

- события заданий из журналов EFT после каждого чтения журналов → сервер возвращает объединённый прогресс
  (он не теряется, когда игра удаляет старые журналы);
- отметки Коллекционера (с локальной копией на случай, если сервер выключен: изменения уйдут, когда он появится);
- последнюю позицию со скриншота (не чаще раза в 2 секунды, на сервере хранится только последняя);
- настройки: тема, горячие клавиши и параметры оверлеев (папка скриншотов не отправляется).

Если сервер не запущен, приложение работает как раньше, локально, и ничего не ломается.

## Где хранятся данные

Всё в одном файле SQLite:

```
server\data\companion.sqlite        (плюс служебные companion.sqlite-wal и companion.sqlite-shm)
```

Путь можно поменять переменной `TARKOV_DB_PATH`. Внутри: аккаунты (пароли — только хэши scrypt),
сессии (только SHA-256 токенов), реферальные коды и счётчики переходов, отметки Кочевников (24 часа),
события заданий, отметки Коллекционера, последняя позиция и настройки пользователей.
Папка `server\data\` исключена из git — не коммитьте её.

## Как сделать стримера

Статус стримера и реферальный код выдаются только владельцем из командной строки (через HTTP нельзя).
Пользователь сначала регистрируется на сайте, затем:

```powershell
npm --prefix server run promote -- streamer@example.com HUNTER_TV
```

Код: 3–24 символа, латиница, цифры, `_` или `-` (приводится к верхнему регистру). Команду можно выполнять
при работающем сервере; статус сохраняется в базе и переживает перезапуск. Повторный запуск с другим кодом
меняет код стримера; пользователи, пришедшие по старому коду, останутся привязаны к нему и в статистике
нового кода не видны — не меняйте код без необходимости.

## Резервная копия

Согласованная копия, можно делать при работающем сервере:

```powershell
npm --prefix server run backup
```

Файл появится в `server\data\backups\companion-<дата>.sqlite`. Можно указать свой путь:
`npm --prefix server run backup -- D:\backup\companion.sqlite`.

Копируйте резервные копии на другой диск или в облако. Восстановление: остановите сервер
(`start-local.ps1 -Stop`), замените `server\data\companion.sqlite` копией, удалите рядом лежащие
`companion.sqlite-wal` и `companion.sqlite-shm` и запустите сервер снова.

## Что пока остаётся в приложении

- Чтение журналов EFT, скриншотов, распознавание экрана, горячие клавиши и оверлеи — это умеет только приложение.
- Локальный профиль (ники режимов, отслеживаемые задания, избранное, уровни убежища, ручные отметки) пока
  хранится в приложении; на сервер уходит прогресс из журналов, Коллекционер, позиция и настройки.
- Каталог (задания, предметы, карты) приложение берёт сначала с сервера (`/v1/catalog/:mode`, общий кэш),
  а если сервер выключен — напрямую с tarkov.dev, как раньше. Английский каталог пока загружается напрямую.
- Отметки Кочевников и поиск профиля по нику работают через сервер, а без него — напрямую.

## Безопасность

- Не открывайте порт 8787 в интернет. Для доступа извне нужен HTTPS (reverse proxy) и `TARKOV_API_TOKEN`.
- Попытки входа и запросы к `/v1/me/*` ограничены по частоте.
- Если пароль или токен попал в чат, журнал или скриншот — считайте его скомпрометированным. Выход из аккаунта
  отзывает текущую сессию; смены пароля и отзыва всех сессий сразу пока нет (сессия живёт 7 дней).
