# Задание для Codex: приложение владельца «Подписки и статистика»

Владелец (16.10.2026): «приложение для отслеживания статистики, который у нас в админке на сайте, чтобы я смог зайти и
посмотреть, сколько оплачено, сколько не оплачено, по каким странам, по каким регионам… пользователи и подписка, оплата…
чтобы я смог сам управлять подписками, добавлять, убавлять что-то и бонусы выдавать».

Сервер уже умеет всё нужное (с 0.6.0.48). Приложение — только интерфейс к готовым запросам. **Серверную логику оплат,
выдачи и подсчёта не дублировать**: всё считает сервер, приложение показывает и отправляет действия.

## Источники истины

- Все запросы, поля, ошибки и лимиты: `docs/codex/owner-admin-api.md`.
- Регионы, Boosty, автовыдача и API Boosty: `docs/payments/payment-regions-and-announcements.md`
  (раздел «API for the subscription tool»).
- Правила проекта: `CLAUDE.md`, `docs/coordination/COORDINATION.md`, `docs/product-roadmap-and-business-model.md`.

## Вход

- `POST https://raidos.app/v1/accounts/login {email, password}` → `{token}`; дальше `Authorization: Bearer <token>`.
  Также вход по коду на почту (`/v1/accounts/email/login/start` → `/email/login`).
- Сессия 7 дней без продления: по 401 — снова экран входа. Не логиниться заново на каждый запуск (лимит 10 сессий на
  аккаунт — старые вытесняются, вход ограничен 10 / 15 мин с IP). Токен хранить в защищённом хранилище ОС
  (Electron `safeStorage` / Keychain), не в открытом файле и не в логах.
- Владелец = почта из `TARKOV_OWNER_EMAILS` с подтверждённой почтой; любой другой аккаунт получает 404 — показать
  «Нет доступа».
- Если приложение браузерное на своём домене — добавить его origin в `WEB_ORIGIN` на сервере (решение владельца и
  оператора сервера). Десктоп (Electron) это не нужно.
- `/v1/admin/*` (локальный токен) из приложения недоступны и не нужны.

## Экраны

1. **Сводка** (`GET /me/admin/stats?from&to`, по умолчанию 30 дней; переключатель периода: сегодня / 7 / 30 / месяц /
   год / свой):
   - пользователи: всего, новые за период, заблокированные;
   - подписки: оплачено деньгами (`activePaid`), выдано бонусом (`activeGranted`: владелец / друзья), пробные,
     бессрочные, истекают через 7 и 30 дней (клик — список пользователей с `expiresBefore`);
   - платившие: всего, в периоде, новые платящие;
   - выручка: всего, по способу оплаты (СБП / SberPay / T-Pay / карта / Boosty), по провайдеру (ЮKassa / Boosty), по
     региону (Россия / СНГ / Мир / не указан), по тарифам, возвраты;
   - рефералы и перевод пробных в оплату.
   - Графики: `GET /me/admin/series?period=day|month|year` и календарь `GET /me/admin/calendar?month=`.
2. **Страны и регионы**: таблица `byCountry` (страна, пользователи, новые, платящие, активные, выручка) с сортировкой и
   поиском; блок `byRegion` (Россия / СНГ / Мир / без страны). Клик по стране — список её пользователей
   (`users?country=XX`).
3. **Пользователи** (`GET /me/admin/users` с фильтрами `q`, `filter`, `country`, `payRegion`, `payer`,
   `expiresBefore`, `registeredFrom/To`, `seenSince`, `autopay`, `sort`, `order`, постранично по 100):
   - колонки: почта, ник, страна, регион, статус, источник подписки (`source`: деньги / бонус / друг / бессрочно /
     пробный), оплачено до, платежей (кол-во / сумма), последний вход, кто пригласил;
   - выгрузка `GET /me/admin/users.csv` с теми же фильтрами.
4. **Карточка пользователя** (`GET /me/admin/users/:id` + полная история платежей `GET /me/admin/payments?q=<email>`
   и Boosty-платежей `GET /me/admin/boosty/payments?email=`):
   - подписка, история платежей и выдач (кто, когда, сколько, причина), устройства
     (`GET …/users/:id/devices`, отозвать устройство);
   - действия: **добавить дни** (`POST …/grant {days, reason}`), **убавить дни** (`POST …/revoke {days, reason}`),
     отменить автоплатёж, заблокировать / разблокировать, завершить все сессии, отвязать аккаунт Таркова, удалить
     аккаунт. Причина обязательна (3–200 символов). Опасные действия — с подтверждением.
5. **Бонусы** (массовая выдача, `POST /me/admin/users/bulk-grant`):
   - выбрать пользователей галочками (`ids`, до 500) или по текущему фильтру списка (`filter`);
   - всегда сначала `dryRun: true` → показать «будет выдано N пользователям» и примеры, затем подтверждение;
   - «Отчёты об ошибках»: награда днями уже есть (`POST /me/admin/bug-reports/:id/reward {days}`).
6. **Платежи** (`GET /me/admin/payments` с фильтрами `from`, `to`, `dateField=paid|created`, `status`, `plan`,
   `provider`, `method`, `region`, `q`; CSV `payments.csv`; отметить возврат `POST /me/admin/payments/:id/refunded`).
7. **Boosty** (`GET /me/admin/boosty`): статус автовыдачи (последняя проверка, ошибка, «Токен Boosty истёк — обновите
   BOOSTY_AUTH»), «Проверить сейчас», пауза, список на проверку (подтвердить / скрыть), сопоставление неизвестных
   уровней, ручное «Подтвердить оплату Boosty».
8. **Приглашения друзей** (`GET /me/admin/invite-rewards`, решения `…/:id/decide`) и **стримеры / выплаты**
   (`/me/admin/streamers`, `/streamer-stats`, `/payouts`) — как в админке сайта.
9. **Журнал действий** (`GET /me/admin/audit`) — кто что выдал / убрал / удалил.

## Требования

- Русский интерфейс (английский по желанию), даты и периоды — по Москве (сервер уже считает по Москве), суммы в рублях.
- Никаких своих расчётов денег и статусов — только данные сервера. Никаких прямых подключений к базе SQLite
  или к Boosty: только API.
- Ошибки сервера — это русские строки в `{error}` (иногда `{code}`): показывать как есть. 429 — подождать
  `Retry-After` и повторить; не долбить сервер (лимиты: 240 чтений / 30 действий в минуту, выгрузки 10 в минуту).
- Персональные данные (почты, телефоны выплат, имена устройств) не кэшировать на диск дольше сессии, не писать в логи,
  не отправлять сторонним сервисам и аналитике.
- Ключи и токены не коммитить. Секреты Boosty живут только на сервере (`BOOSTY_AUTH`, `BOOSTY_CLIENT_ID`) — приложению
  они не нужны.
- Перед изменением оплат, подписок, рефералов — свериться с `docs/product-roadmap-and-business-model.md`.

## Чего на сервере нет (если понадобится — сначала договориться, не делать в обход)

- Выдачи именно «пробных» дней (есть только оплаченные дни через grant).
- Индивидуального лимита устройств для одного пользователя (лимит общий).
- Списка «кто сейчас в сети» по пользователям (есть только количество `GET /me/admin/online`).
- Частичных возвратов в статистике.

## Готово, когда

- Владелец входит своей почтой, видит сводку за любой период, страны и регионы, ищет и фильтрует пользователей,
  выгружает CSV, добавляет и убирает дни одному и многим (с пробным прогоном), подтверждает Boosty-оплаты, видит журнал.
- Проверено на тестовом сервере (`npm run server:dev`) и на копии без живой базы; живую базу в Git не копировать.
