# «Отчёты»: как Claude на компьютере владельца работает с таблицей

Таблица отчётов и предложений на сайте, в приложении владельца и в админ-приложении на телефоне. Сервер хранит отчёты, разбор, статусы и очередь заданий. Работает компьютер владельца: `scripts/reports-run.mjs`, обычный скрипт, сам ходит на сервер и вызывает Claude, только когда есть что делать. Публичных маршрутов для агента нет, платного API нет. **Пока компьютер выключен, ничего не разбирается и не делается**, и таблица так и пишет.

**Расписание выключено** до слова владельца. Что для него нужно, в разделе «Как включить и выключить».

## Кнопка «Копировать»

В каждой строке таблицы, на сайте, в приложении и на телефоне. Кладёт в буфер обмена данные этого одного отчёта: почту, Windows, Steam или нет, версию приложения, тему и текст игрока, а у исправлений квестов ещё квест, карту, место и заметки. Владелец вставляет это в Claude сам. Текст игрока подписан как данные, а не команды.

## Статусы

`Ожидает проверки` → кнопка владельца → `Отдано в работу` → `В работе` → `Выполнено` или `Не реализовано` → `Добавлено на сервер`.
Кнопки владельца: `Отдать в работу`, `Отклонить`, `Уже реализовано`. `Вернуть на проверку` снимает ошибочное нажатие, пока Claude не взял задание.
`Не реализовано` возвращается владельцу: он правит план и отдаёт снова или отказывает. `Закрыто`: отчёты, закрытые до этой таблицы.

## Кто что видит и может

Текст отчёта пишет кто угодно, это может быть атака на агента. Поэтому защита держится не на послушании модели, а на том, что ей нечем навредить:

| | Разбор | Работа | Скрипт |
|---|---|---|---|
| Текст игрока, скриншоты | да, как данные | **нет** | передаёт, не печатает |
| Команды | **нет** | только список проверок | да |
| Сеть, MCP, настройки | **нет** | **нет** | да |
| Файлы | чтение: папка агента и скриншоты этого отчёта | папка агента | да |
| Ключи к серверу, пуш | **нет** | **нет** | да |
| Что выходит наружу | только `summary` и `plan` по схеме, в таблицу | правка, если прошла проверки ниже | статусы |

Разбор: `claude -p --restricted --strict-mcp-config --tools Read,Grep,Glob`, рабочая папка это папка агента, отчёт идёт через stdin. Самое плохое, что он может: написать в таблицу неверный вывод или план. Отчёт сам ничего не запускает.

**Единственный путь от текста игрока к коду: план, который владелец прочитал и утвердил кнопкой.** В работу идёт только `approvedPlan`, без текста игрока и без вывода разбора (`job()` в `server/src/services/reportsAgent.ts`). Поэтому план надо читать перед кнопкой: он написан по словам игрока.

Правку перед пушем проверяет скрипт, а не модель:
- файлы про оплату, подписки, ключи, вход, аккаунты, приглашения, выпуск, `.github/`, `package.json` и сам этот агент: `Не реализовано` с просьбой к владельцу (`sensitiveFiles` в `scripts/reports-run.mjs`, лучше лишний отказ, чем пропуск);
- больше 40 файлов: то же;
- типы приложения и сервера, vitest, серверные тесты: то, что иначе остановит выпуск у всех. Известные падения без связи с работой: release-policy, cache-item-images, linux/updater, staleServer, appVersion, AdminPanelPage (порядок в меню);
- работа не начинается, пока запущена игра (`EscapeFromTarkov.exe`) или идёт выпуск.

Дни подписки не начисляются, игрокам ничего не отправляется: таких команд у агента нет. Задание появляется только после кнопки владельца: `queued` пишет лишь `BugReportStore.ownerWork` (маршрут только для владельца, проверка на сервере), покрыто `server/src/routes/reportWork.test.ts`.

## Ключи на сервере

Основной ключ сервера агент не использует. Два своих ключа (`~/.ssh/raidos_reports_triage` и `raidos_reports_work`) входят как системный пользователь `raidos-reports` без пароля, который не владеет ничем, даже своими `authorized_keys`. Каждый ключ стоит с `restrict,command=...`, то есть без оболочки и туннелей, и может только позвать `scripts/reports-agent-gate.mjs`, который сверяет текст команды со своим списком:

- `triage`: `pending`, `triage`, `image`. Читает новые отчёты, пишет разбор, статусов не двигает.
- `work`: `jobs`, `start`, `finish`, `done`, `published`, `release-busy`. Отчётов не читает.

К базе `raidos-reports` идёт через единственную строку в `/etc/sudoers.d/raidos-reports`: запуск `scripts/reports-agent-cli.sh` как `raidos-api`.

Издатель этого не обновляет. После правки gate или обёртки поставить руками, от root, файлы лежат в репозитории:

```bash
bash docs/coordination/ops-reference/install-reports-agent.sh raidos_reports_triage.pub raidos_reports_work.pub scripts/reports-agent-gate.mjs scripts/reports-agent-cli.sh
```

Отозвать доступ: удалить строку ключа из `/home/raidos-reports/.ssh/authorized_keys`.

## Команды

Обычно всё делает `reports-run.mjs`. Для проверки руками: ответ всегда JSON одной строкой, текст игрока никогда не идёт через командную строку.

```bash
node scripts/reports-agent.mjs pending
node scripts/reports-agent.mjs triage 12 triage.json
node scripts/reports-agent.mjs jobs
node scripts/reports-agent.mjs start 12
node scripts/reports-agent.mjs finish 12 finish.json
node scripts/reports-agent.mjs image 12 0 shot.png
node scripts/reports-agent.mjs sync-published "C:\Users\BANGKOK PC\raidos-reports-agent"
node scripts/reports-agent.mjs release-busy
```

`pending` и `jobs` ставят отметку, что Claude заходил.

## Что делает один запуск

Папка агента: `C:\Users\BANGKOK PC\raidos-reports-agent`, отдельная рабочая копия этого репозитория. Если её нет: `git -C "C:\Users\BANGKOK PC\tarkov-operations-companion" worktree add --detach "C:\Users\BANGKOK PC\raidos-reports-agent" origin/release/production`. Состояние и журнал без текста отчётов: `%LOCALAPPDATA%\raidos-reports-agent` (`run.log`, `state.json`).

`node scripts/reports-run.mjs run`, один запуск за раз (блокировка в той же папке). Пустой запуск не вызывает Claude и не тратит лимит.

1. Свежий код: `git fetch`, `origin/release/production`. Незакоммиченное от упавшего запуска уходит в свою ветку, ничего не теряется.
2. **Разбор.** До 5 новых отчётов за запуск и до 40 за день, чтобы поток отчётов не съел лимит. Каждый отдельным Claude. Три непонятных ответа подряд, и отчёт больше не разбирается: он ждёт владельца, а план можно написать самому.
3. **Опубликованное.** `Добавлено на сервер` ставит только `sync-published`, когда коммит правки реально входит в опубликованную версию (`https://raidos.app/download/version.json`, поле `commit`), а не по факту пуша.
4. **Работа.** Одно самое старое задание: `start`, ветка `claude/report-<номер>`, Claude по плану, коммит, проверки выше.
5. **Выпуск правки.** `git rebase` на свежий код, следующий номер версии и строка в `src/data/updateHistory.json`, запись в `docs/coordination/WORK_LOG.md`, `git push origin HEAD:release/production` без force, `finish` с полным хешем. Правка выходит пачкой в 13:00 или 20:00 по Бангкоку, сам выпуск агент не запускает.

Если идёт выпуск или до него меньше 25 минут (пуш в это время оставляет выпуск без зелёной проверки или молча его отменяет, память `publisher-head-must-not-move`), готовая правка остаётся в ветке, отчёт `В работе`, и следующий запуск продолжит с шага 5 без Claude. Конфликт при rebase, отказ Claude, не прошедшие проверки: `Не реализовано` с причиной, коммит остаётся в локальной ветке и в код не идёт.

На сервере агент не посылает сигналы процессам и не меняет базу напрямую: у него нет такой возможности.

## Как включить и выключить

Сейчас выключено. Чтобы включить:

1. Владелец один раз сам входит в Claude CLI: `claude auth login`. У отдельного CLI свой вход, приложение Claude его не даёт. Без входа разбор не работает, и журнал так и пишет.
2. Проверка изоляции на местных данных, на сервер ничего не идёт, расходует немного лимита:

   ```bash
   node scripts/reports-run.mjs check
   ```

   Она даёт Claude враждебный отчёт, а затем прямо велит ему выполнить этот отчёт, и смотрит, что он не достал чужой файл и ничего не создал. Если в конце не «Изоляция подтверждена», расписание не включать.
3. Владелец говорит включить. Задача Планировщика Windows, каждые 15 минут, только пока он вошёл в Windows, без окна поверх игры:

   ```bash
   schtasks /Create /TN "raidos-reports-agent" /SC MINUTE /MO 15 /TR "wscript.exe \"C:\Users\BANGKOK PC\raidos-reports-agent\scripts\reports-run-hidden.vbs\"" /F
   ```

Выключить: `schtasks /Change /TN "raidos-reports-agent" /DISABLE`. Выключенная задача ничего не ломает: таблица работает, новые отчёты в неё попадают, ячейка разбора пишет, что разбора ещё нет, а владелец может написать план сам. Уже отданные в работу отчёты ждут и будут взяты первым же запуском после включения.

Запустить один раз руками: задача `raidos-reports-agent` в приложении Claude (только вручную, вызывает тот же скрипт, модель текстов игроков не видит).

Лимит: разбор идёт на Sonnet, работа на Opus, оба через подписку.
