# Сервер на ноутбуке (постоянно включён)

Ноутбук держит включёнными API-сервер, сайт с личным кабинетом и публичную ссылку для друзей.
Отдельно ставить ничего не нужно: это тот же exe приложения, запущенный в режиме сервера
(`--server-mode`). Игровые функции (оверлеи, чтение экрана, горячие клавиши) в этом режиме выключены,
запрос прав администратора не появляется, окно запускается свёрнутым.

## Две версии приложения

С версии, где появился вход в аккаунт, собираются два разных exe (`electron/buildEdition.ts`):

- **Версия владельца** (`OWNER_BUILD=1`): «Аккаунт сервера», кнопка «Сервер» в верхней панели, сервер и сайт на
  этом компьютере, ссылка для друзей, оплата, стримеры. Её запускают на ноутбуке-сервере и на вашем игровом ПК.
- **Версия для игроков** (по умолчанию): при первом запуске окно входа в аккаунт, в профиле «Личный кабинет».
  Никаких настроек сервера в ней нет, ключи `--server-mode`, `--enable-local-server` и `--enable-tunnel` она
  игнорирует. Адрес сервера вшит при сборке: `https://raidos.app` (или `TARKOV_DEFAULT_SERVER_URL`).

Кнопка «Скачать для Windows» на сайте отдаёт **только версию для игроков**. Её кладёт рядом с сервером
`Server-Laptop-Setup.cmd`: `%LOCALAPPDATA%\TarkovOperatorServer\client\Raid OS <версия>.exe` и
`client\version.json`. Если этой папки нет, сайт отвечает «Версия приложения для игроков ещё не опубликована»:
exe владельца чужим людям не раздаётся. Версия владельца не обновляет себя версией для игроков
(`/download/version.json` сообщает `edition: "client"`).

## Установка

1. Скачайте на ноутбук все части `RaidOS.part*` (версия владельца), `RaidOSClient.part*` (версия для
   игроков) и `Server-Laptop-Setup.cmd` в одну папку.
2. Запустите `Server-Laptop-Setup.cmd`. Скрипт:
   - останавливает запущенный сервер (и новый `Raid OS.exe`, и старый `Tarkov Operator.exe`);
   - собирает exe владельца в `%LOCALAPPDATA%\TarkovOperatorServer\Raid OS Server.exe`. На ноутбуке, настроенном
     до переименования в Raid OS, файл сохраняет старое имя `Tarkov Operator Server.exe`, чтобы ярлык
     автозапуска продолжал работать;
   - собирает версию для игроков в `%LOCALAPPDATA%\TarkovOperatorServer\client\` и пишет рядом подписанный
     `version.json` (это и есть «загрузить файл для клиента на сайт», подпись см. ниже в «Автообновление»);
   - проверяет контрольные суммы;
   - запускает сервер с `--server-mode --enable-tunnel`.
3. Приложение запускает сервер (порт 8787), сайт (порт 5202) и публичную ссылку `https://….trycloudflare.com`.
   Ссылку видно в свёрнутом окне: кнопка «Сервер» в верхней панели.

Настройки ноутбука (их меняете вы сами, скрипт их не трогает):

- Параметры → Система → Питание: «Переводить в спящий режим» — «Никогда» (при питании от сети).
  Иначе сервер засыпает вместе с ноутбуком.
- Действие при закрытии крышки — «Ничего не делать», если ноутбук будет стоять закрытым.
- Автозапуск при включении Windows (по желанию). Нажмите Win+R, введите `shell:startup` и создайте в
  открывшейся папке ярлык на `%LOCALAPPDATA%\TarkovOperatorServer\Raid OS Server.exe` (или `Tarkov Operator Server.exe`,
  если ноутбук настроен до переименования).
  В свойствах ярлыка допишите к объекту ` --server-mode --enable-tunnel`. Чтобы отключить автозапуск,
  удалите ярлык.

## Перенос базы с основного ПК

База одна, это файл SQLite в папке данных приложения. Папка сохранила имя со времён Tarkov Operator — после
переименования в Raid OS приложение продолжает работать с ней, данные никуда не переезжают:

```
%APPDATA%\Tarkov Operator\server\companion.sqlite
```

Если на ПК есть старая папка `%APPDATA%\Tarkov Operations Companion Beta`, база лежит в ней: `server\companion.sqlite`.

Как перенести базу:

1. На основном ПК закройте приложение. Сервер остановится, и база закроется.
2. Скопируйте `companion.sqlite` на флешку. Если рядом лежат `companion.sqlite-wal` и `companion.sqlite-shm`,
   скопируйте и их.
3. На ноутбуке закройте Raid OS Server.
4. Положите файлы в `%APPDATA%\Tarkov Operator\server\` с заменой и запустите сервер снова.
5. На основном ПК выключите «Сервер и сайт на этом компьютере» (кнопка «Сервер»). Иначе будут два сервера
   с разными базами.

Аккаунты, стримеры, прогресс и отметки хранятся только в этой базе. Её не удаляют ни обновление, ни замена exe.

## Как проходит обновление

Код меняется не на ноутбуке, а в репозитории. Порядок такой:

1. Правки делаются в Claude Code и попадают в GitHub.
2. Из репозитория собирается новый exe.
3. На ноутбук кладутся новые части и новый `Server-Laptop-Setup.cmd`.
4. Запускается `Server-Laptop-Setup.cmd`. Скрипт:
   - закрывает работающий сервер штатно, база закрывается корректно;
   - заменяет exe и снова запускает сервер.

Простой около минуты. База остаётся. Друзья после обновления сервера могут скачать новый exe на сайте:
кнопка «Скачать для Windows» отдаёт версию для игроков из папки `client`.

Перед крупными обновлениями сделайте копию базы. Для этого закройте сервер и скопируйте `companion.sqlite`
в другое место.

## Автообновление сервера (ноутбук обновляет себя сам)

Ноутбук может обновляться без `Server-Laptop-Setup.cmd`: он сам забирает новые сборки из **закрытого**
репозитория релизов на GitHub (по умолчанию `proraa69-creator/raidos-releases`). Телефон для этого не нужен, а сайт
ничего на ноутбук не загружает. В админ-панели сайта во вкладке «Обновление» видно состояние, там же есть кнопки
«Проверить сейчас», «Установить сейчас» и «Откатить на предыдущую».

**По умолчанию установка ручная.** Ноутбук сам проверяет, скачивает и проверяет новую сборку, затем показывает
«Скачано и проверено, ждёт установки», присылает уведомление Windows и пишет строку в журнал наблюдателя. Ставится
сборка только после кнопки «Установить сейчас»: в приложении на ноутбуке («Автообновление сервера») или на сайте
(Админ-панель → «Обновление»). Режимы «сразу» и «только ночью, 03:00–06:00» можно выбрать в приложении на ноутбуке.
Настройки, сохранённые до появления ручного режима без явного выбора, считаются ручными.

### Как устроен репозиторий релизов

```
latest.json                              {"build": <номер сборки>, "path": "releases/<номер сборки>"}
releases/<build>/RaidOS-update.json      подписанный манифест
releases/<build>/RaidOS.part0..N         exe владельца частями (≤ 25 МБ)
releases/<build>/RaidOSClient.part0..N   exe для игроков частями
```

- `RaidOS-update.json` создаёт `scripts/split-exe-for-chat.sh`, если задан ключ обновлений
  (`RAIDOS_UPDATE_SIGNING_KEY_FILE` или `RAIDOS_UPDATE_SIGNING_KEY`, тот же ключ, что подписывает `version.json` игроков).
  Подписью делает её `scripts/sign-server-update.mjs`. В манифест входят версия, номер сборки и коммит версии владельца,
  размер и SHA-256 обоих exe, размер и SHA-256 каждой части, а также подписанный `version.json` игроков. Подпись
  Ed25519 ставится над каноническим текстом из `electron/serverUpdateManifest.ts`. Префикс `raidos-server-update-v1`
  отличается от префикса манифеста игроков, поэтому одну подпись нельзя выдать за другую.
- `scripts/publish-release.sh <папка с частями> <локальный клон репозитория релизов>` проверяет подпись встроенным
  ключом и каждую часть. Затем копирует файлы в `releases/<build>/`, переводит `latest.json` вперёд (назад только с
  `ALLOW_OLDER=1`), оставляет 3 последние сборки (старые удаляются обычным коммитом) и делает коммит. Отправку
  (`git push`) выполняете вы или сборочная сессия.
- История git растёт примерно на 260 МБ с каждым релизом. Когда репозиторий станет большим, его можно пересоздать:
  ноутбуку нужен только `latest.json` и последняя папка.

### Что делает ноутбук

1. Раз в 15 минут (первый раз через 2 минуты после запуска) читает `latest.json` через GitHub REST API с токеном. Если
   ничего не изменилось, проверка стоит один запрос 304.
2. Если сборка новее установленной, скачивает `RaidOS-update.json` и проверяет подпись **ключом, встроенным в
   приложение** (`electron/updateSigningKey.ts`). Если подпись не сходится, ничего не скачивается. Номер сборки в
   `latest.json` должен совпадать с подписанным.
3. Скачивает части в `%APPDATA%\Tarkov Operator\server\self-update\staging\<build>\`. Каждая часть проверяется по
   подписанному размеру и SHA-256, лишние байты обрывают загрузку. Если загрузка прервалась, она продолжается с
   первой непроверенной части.
4. Собирает оба exe и проверяет их размер и SHA-256, а также подпись `version.json` игроков.
5. Ждёт установки. В режиме «вручную» (по умолчанию) — кнопки «Установить сейчас» (на сайте она требует
   подтверждения `{ "confirm": true }`, пишется в журнал администратора и ограничена 3 нажатиями за 10 минут); в режиме
   «сразу» ставит сразу; в режиме «только ночью» — в 03:00–06:00 по времени ноутбука. Перед самой установкой проверяет
   всё ещё раз с нуля, чтобы поймать файл, изменённый на диске.
6. Делает копию базы (`before-restart`). Публикует версию для игроков в `client\` (как `Server-Laptop-Setup.cmd`), а
   прежнюю кладёт в `previous\client\`. Текущий exe сохраняет как `previous\<имя exe>` и запоминает его SHA-256.
7. Запускает маленький помощник на PowerShell (`self-update\update-helper.ps1`, скрытое окно, `-ExecutionPolicy
   Bypass`). Помощник стартует через короткий запускатор (`Start-Process`), поэтому он не входит в дерево процессов
   приложения и переживает его закрытие. Приложение ждёт до 20 секунд, пока помощник не запишет `helper.pid`. Если
   помощник не запустился (PowerShell заблокирован, антивирус), перезапуск отменяется, сервер продолжает работать в
   прежней версии, а сбой «помощник не запустился» попадает в историю, журнал и отчёты GitHub. Иначе приложение
   закрывается штатно.
   Приложение — portable-exe electron-builder: `Raid OS Server.exe` распаковывает внутренний exe в `%TEMP%` и удаляет
   эту папку после его выхода. Помощник ждёт выхода **обоих** процессов: внутреннего (его pid) и обёртки (процесс с
   путём `Raid OS Server.exe`). Если за 90 секунд они не закрылись, помощник останавливает оба (`taskkill /T`). Затем
   он заменяет exe и запускает его с теми же ключами (`--server-mode` и, если был, `--enable-tunnel`). В течение
   30 секунд он проверяет, что процесс действительно появился; если нет, сразу делает откат.
8. **Проверка здоровья: 2 минуты.** Новая сборка должна дважды подряд ответить на `/health` своим номером сборки и
   открыть сайт. Новая версия проверяет себя и сама, а помощник опрашивает её независимо. Если за 2 минуты проверка
   не пройдена, помощник останавливает новую версию (дерево обёртки и внутренний exe из `app.pid`, который пишет
   новая версия при старте; процессы «по имени» не трогаются, чтобы не закрыть копию игрока на том же ноутбуке),
   возвращает `previous` и прежнюю версию для игроков, запускает их и показывает уведомление Windows.
9. После запуска приложение записывает итог в историю (вкладка «Обновление»), в журнал наблюдателя и в уведомление.
   Откат также уходит в «Отчёты об ошибках (GitHub)». Откаченная сборка больше не ставится автоматически, новая
   ставится.

Старые сборки и та же самая сборка автоматически не ставятся никогда. Вернуться назад можно только кнопкой
«Откатить на предыдущую» (в приложении или на сайте). Она возвращает сохранённый `previous` после проверки его
SHA-256, проходит тот же перезапуск с проверкой здоровья и помечает оставленную сборку как «не ставить».

### Диагностика: журнал помощника

Каждый шаг перезапуска записывается с отметкой времени в журнал:

```
%APPDATA%\Tarkov Operator\server\self-update\update-helper.log
```

Строки `[app]` пишет приложение перед запуском помощника, `[launcher]` — запускатор, `[helper]` —
сам помощник. Это ожидание выхода обоих процессов, результат замены exe, `Start-Process` и появление процесса, каждая
проверка здоровья, шаги отката и ошибки. Рядом лежит протокол PowerShell `update-helper.transcript.log`. Журнал
прошлого перезапуска сохраняется как `update-helper.prev.log`.

Если после запуска приложения остался незавершённый перезапуск, а помощника уже нет (не записал итог: закрыт,
заблокирован антивирусом, ноутбук перезагрузился), приложение записывает сбой «помощник обновления пропал»
(`helper-lost`). Сбой виден в истории (вкладка «Обновление» и панель на ноутбуке, с концом журнала), в журнале
наблюдателя и в уведомлении. Он также уходит в «Отчёты об ошибках (GitHub)» с концом `update-helper.log`, очищенным
тем же фильтром, что и остальные отчёты. Такая сборка не помечается «не ставить»: её можно поставить ещё раз кнопкой.

### Настройка (один раз)

1. На GitHub создайте **закрытый** репозиторий `raidos-releases`.
2. Создайте токен: GitHub → Settings → Developer settings → Fine-grained tokens → Generate new token.
   В Repository access выберите Only select repositories → `raidos-releases`. В Permissions укажите
   **Contents: Read-only**, больше ничего. Срок действия выберите сами и не забудьте продлить токен до истечения.
3. На ноутбуке разверните окно Raid OS Server → «Сервер» → «Автообновление сервера» → «Настроить». Впишите
   репозиторий и вставьте токен, нажмите «Сохранить» и включите переключатель. Время установки по умолчанию —
   «вручную»; менять его не обязательно.
   Токен хранится зашифрованным (DPAPI) и больше не показывается.
4. Первый раз ноутбук обновляют вручную `Server-Laptop-Setup.cmd` сборкой, в которой автообновление уже есть.

### Модель угроз «Обновление с телефона»

Что защищаем: ноутбук запускает только exe, который подписан вашим ключом.

- **Подделка релиза** (чужой коммит в репозиторий, украденный токен GitHub, подмена ответа по сети). Ноутбук
  проверяет подпись манифеста ключом, вшитым в приложение, а каждую часть и оба exe сверяет по подписанным SHA-256.
  Ключа из загрузки, из репозитория или с сайта не берёт никогда. Закрытый ключ хранится только у сборщика и
  никогда не попадает на ноутбук, в репозиторий релизов или в чат. Если украдут токен чтения, злоумышленник сможет
  только скачать ваши exe.
- **Откат на старую уязвимую сборку** (подменённый `latest.json`). Сборка не новее установленной автоматически не
  ставится. `latest.json` подписью не защищён и только указывает, где искать.
- **Захваченная сессия владельца на сайте.** Сайт умеет только читать состояние и нажимать «Проверить сейчас»,
  «Установить сейчас» или «Откатить на предыдущую». Установка и откат идут только с подтверждением, все действия
  попадают в журнал администратора, на запросы есть лимиты. «Установить сейчас» ставит только сборку, которую ноутбук
  сам скачал и проверил: запрос не несёт ни файла, ни номера сборки, ни адреса. Сайт
  не может передать ноутбуку файл, сменить репозиторий или токен: эти настройки есть только в приложении на ноутбуке.
  Маршрутов загрузки на сервере нет. Авторизация идёт по Bearer, без cookie, поэтому CSRF не применим.
- **Подмена файлов на диске ноутбука между загрузкой и установкой.** Всё проверяется ещё раз прямо перед
  установкой, а копия exe проверяется после копирования. Сохранённый `previous` перед откатом сверяется с
  запомненным SHA-256. Тот, у кого есть права записи в профиль Windows ноутбука, и так управляет сервером: это вне
  модели.
- **Сломанная новая сборка.** Через 2 минуты срабатывает автоматический откат, копия базы сделана до перезапуска.
- Процесс API (он принимает запросы из интернета) может попросить у приложения только состояние, проверку, установку
  уже проверенной сборки и откат (`electron/apiChannel.ts`). Сам он ничего не устанавливает.

Не проверено вне Windows: запуск помощника через запускатор, ожидание обоих процессов portable-exe, замену exe,
перезапуск, журнал `update-helper.log` и откат нужно один раз проверить на настоящем ноутбуке. Для этого выпустите
тестовую сборку, нажмите «Установить сейчас» и прочитайте журнал. Затем выпустите заведомо «сломанную» сборку,
например без сайта, и убедитесь в откате. Пока это не сделано, оставляйте режим «вручную» и ставьте обновления, когда
есть доступ к ноутбуку.

## Отчёты об ошибках (GitHub)

«Сервер» → «Отчёты об ошибках (GitHub)» на ноутбуке. Ошибки сервера становятся задачами в репозитории
(по умолчанию `proraa69-creator/tarkov-operations-companion`) с метками `auto-report` и `server`, и Claude может их
исправить. В отчёты попадают:

- необработанные исключения и ответы 5xx API со стеком;
- инциденты «Стража»: падения по кругу, перезапуски из-за ошибок, проверка базы, неудавшаяся копия;
- сервисы, которые наблюдатель не смог починить;
- откаты автообновления.

Перед отправкой из текста удаляются IP-адреса, e-mail, токены и ключи (`re_…`, `live_…`, `test_…`, `github_pat_…`,
`eyJ…`, `Bearer …`, длинные hex и base64), параметры запросов (`?…`) и пути пользователя (`%USERPROFILE%`). В отчёт
входят версия, сборка, коммит, отпечаток (имя ошибки и верхние кадры стека кода приложения), время первого и
последнего случая и число повторов. Одна ошибка даёт одну открытую задачу: повтор добавляет комментарий не чаще
раза в час. Новых задач не больше 5 в сутки. Без интернета отчёты ждут в очереди на диске.

Токен: GitHub → Settings → Developer settings → Fine-grained tokens. В Repository access выберите только этот
репозиторий, в Permissions укажите **Issues: Read and write**, больше ничего. Кнопка «Проверить доступ» создаёт и сразу
закрывает тестовую задачу. По умолчанию отчёты выключены.

## Автообновление приложения у игроков

Приложения игроков обновляются сами, только с сервера, вшитого в сборку (`https://raidos.app`, то есть сайт
ноутбука по постоянному адресу). Адрес, введённый в профиле («Адрес сервера»), для обновлений не используется:

- при запуске и затем раз в 6 часов приложение спрашивает сайт (`/download/version.json`), какая
  сборка версии для игроков там лежит (версия владельца её не ставит);
- сборка предлагается, только если `version.json` подписан ключом обновлений (Ed25519). Подпись покрывает версию,
  номер сборки, коммит, редакцию, размер и SHA-256 exe, поэтому подменённый exe или чужой сервер приложение не
  обновят (в настройках: «Версия на сервере без действительной подписи»);
- если она новее, в верхней панели появляется кнопка «Обновить приложение»;
- по нажатию новый exe скачивается рядом со старым и проверяется по подписанным размеру и SHA-256. Затем приложение
  закрывается, файл заменяется, и запускается новая версия. Настройки и прогресс сохраняются.

Подпись ставит `scripts/split-exe-for-chat.sh` (через `scripts/sign-client-release.mjs`), если при сборке задан
закрытый ключ: `RAIDOS_UPDATE_SIGNING_KEY_FILE=<путь к PEM>` или `RAIDOS_UPDATE_SIGNING_KEY` (сам PEM или его
base64). Открытый ключ вшит в приложение (`electron/updateSigningKey.ts`). Закрытый ключ не хранится ни в
репозитории, ни на ноутбуке. Без ключа скрипт не соберёт части для игроков, кроме `ALLOW_UNSIGNED=1`: тогда сайт
отдаёт exe для скачивания, но автообновления у игроков не будет.

Значит, для обновления у всех достаточно обновить ноутбук: опубликовать релиз в репозиторий релизов
(«Автообновление сервера» выше) или запустить `Server-Laptop-Setup.cmd`. Ноутбук обновляет себя только из
репозитория релизов, а не через этот механизм. Копия на другом ПК, которая запускает свой сервер (`127.0.0.1`), себя
не обновляет. На основном игровом ПК впишите в
«Адрес сервера» постоянный адрес ноутбука, тогда он тоже будет получать обновления.

Автообновление работает, начиная с версии, в которой оно появилось: её один раз ставят вручную.

## Постоянный адрес (Cloudflare Tunnel)

Бесплатная быстрая ссылка (`trycloudflare.com`) меняется при каждом запуске сервера. Постоянный адрес даёт
туннель с именем в вашем аккаунте Cloudflare.

Важно понимать, как это работает. На Cloudflare **ничего не загружается**: сервер, сайт и база остаются на
ноутбуке. Cloudflare только держит постоянный адрес (например `https://tarkov.ваш-домен.ru`) и пересылает
запросы на ноутбук через защищённое соединение. Открывать порты на роутере не нужно. Выключен ноутбук —
выключен и сайт.

Что нужно от вас (аккаунт и покупку домена делаете вы сами):

1. Бесплатный аккаунт на https://dash.cloudflare.com.
2. Свой домен, добавленный в Cloudflare. Его можно купить прямо в Cloudflare (Domain Registration),
   от ~$10 в год, или перенести туда DNS уже имеющегося домена.
3. Создайте туннель: Zero Trust → Networks → Tunnels → Create a tunnel → тип **Cloudflared** →
   имя, например `tarkov-laptop`. Ставить cloudflared по инструкции на странице не нужно: приложение само
   скачивает и запускает его.
4. На той же странице есть команда установки с длинным токеном `eyJ…`. Скопируйте её целиком или только
   токен. **Токен — это пароль туннеля**: не отправляйте его в чат и никому не показывайте. Если он
   утёк, удалите туннель и создайте новый.
5. Добавьте публичный адрес: Public Hostname → Add:
   - Subdomain `tarkov`, Domain — ваш домен;
   - Service: тип `HTTP`, URL `127.0.0.1:5202`.
6. На ноутбуке разверните окно Raid OS Server → кнопка «Сервер» → «Постоянный адрес» → «Настроить».
   Введите адрес (`tarkov.ваш-домен.ru`), вставьте токен и нажмите «Сохранить». Токен хранится на ноутбуке
   в зашифрованном виде (DPAPI Windows).
7. Когда в строке «Ссылка» появится «работает», адрес готов. Друзья открывают его в браузере. В приложении
   они вписывают его один раз: Профиль → «Адрес сервера». После перезапусков и обновлений адрес не меняется.

Убрать постоянный адрес можно кнопкой «Убрать»: приложение вернётся к бесплатной меняющейся ссылке.

### Если хочется совсем без ноутбука

Сервер можно перенести в облако Cloudflare: Workers + база D1, есть бесплатный лимит. Тогда он работает
круглосуточно, а обновление — это одна команда публикации. Но код сервера для этого нужно переписать
(сейчас он использует `node:sqlite` и работает как обычная программа), это отдельная большая задача.
